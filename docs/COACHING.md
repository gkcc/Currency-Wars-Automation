# 带教协议：每回合一份方案，由 Codex 执行

## 开始条件

确认当前用户允许操作此局，确认真实游戏窗口和当前可用的电脑输入/截图工具。仅本次带教方案获得用户批准，不等于未来每局永久许可。如果用户要求停止，立即停止输入。

默认 **回合开始由 Codex 主动提出方案，用户负责批准或调整**。审批的是战略，不是逐点击的技术脚本。用户认可后 Codex 亲自操作，用户无需点鼠标。

## 一屏可读的回合提案

按以下六项简短汇报（不是长篇推理）：

1. 本轮目标：冲段保胜 / 完成指定奖励 / 过渡并积累资源。
2. 经济：当前已核金币；本轮购牌上限、免费与付费刷新次数、购牌预留、是否买经验、最终预计留资及理由。
3. 角色：买谁、卖谁、保留谁、何时切换羁绊，以及场上/后台部署方向。
4. 装备：目前**真实已持有**什么、可穿给谁、是否值得合成/重铸；过渡角色可先穿、核心到手再卸下转移。
5. 战前风险：下一战生存风险、资源紧急缺口、策略中不确定的机制。
6. 计划变更触发器：刷新到关键核心/投资重大变化、金币不符、血量告急、羁绊达标或原方案收益失效。

给出“同意后我会执行本回合并回读战果”的明确提示。**不要求用户反复确认每一笔合法既定购买。**

## 获得批准之后

- 先处理必要的奖励和容量，再整理角色和经济，通常在出战前完成装备及阵容调整；这些是工作检查点，不是不可变的先后法律。
- 在有明确预算、真实价格和受检输入时执行。每轮普通变化只局部重算。
- 高风险分支（不可逆合成、重置、明显超出预算、彻底换核心策略）必须重新让用户确认，不能把普通授权扩大成重大改变。
- 正常行动前后检查游戏状态。商店未打开时刷新键可能没效果；拖装备、出售、买经验可能因动画未生效，按实际资源变化判断，未知不连点。
- 奖励确认、开箱、出战、结算是不同阶段；实际看到奖励到账/正式结算才能标完成。

## 每轮执行结束的简报

只汇报实际完成动作、当前战力/羁绊/人口、剩余资源、下一回合重点。不要输出几百行工具日志或技术审查；需要时引用原始截图或真实操作收据。

## 真正卡住时

最多做有限、合理的现有工具重观察和合法恢复。没有入口就停下并告诉用户问题；**不要转入修程序/加控制器/删保护/改权限的支线**。
