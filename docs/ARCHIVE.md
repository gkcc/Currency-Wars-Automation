## 为什么新主线没有保留旧程序？

旧版 GUI、Worker、broker、MCP、OCR、经济宏、实验求解器、测试、Windows 打包/启动工具和上百份工程日志彼此依赖。将任何一个部分搬进新 main 可能重新引入审批、等待或无效入口；若单独留下几个文件，则容易产生看似有工具、实际上不能运行的半成品。

1. 优先使用当前 Codex 环境里**已经存在且经用户授权**的截图、键鼠工具。先确认能安全观察，不要为缺工具自动安装新框架。

3. 任何输入操作都只允许一个实际控制者，遵守用户暂停/停止，窗口确认、输入已提交但后果未知时不盲重放。
4. 当前正在运行的 Windows 实例不会因为远端 GitHub 上创建新分支/合并而自动关闭。**不要在活跃进程使用原源码时强行 git pull、切换 main 或删除本地旧文件**；保护未提交修改。
5. 若当前环境没有可用合法输入工具，应直说“当前只能做战略带教，无法自动点击”，并给用户最短可操作的选项；不能伪造成功。
