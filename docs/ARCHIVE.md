## 为什么新主线没有保留旧程序？

旧版 GUI、Worker、broker、MCP、OCR、经济宏、实验求解器、测试、Windows 打包/启动工具和上百份工程日志彼此依赖。将任何一个部分搬进新 main 可能重新引入审批、等待或无效入口；若单独留下几个文件，则容易产生看似有工具、实际上不能运行的半成品。

带教模式的核心交付是**一名 Codex 玩家、一份经批准的整回合计划、简单可用的电脑观察/操作工具和实际游戏结果**。新主线现在增加 `tools/game_io.py`，不包含旧 GUI、Worker、MCP 或完整输入 broker。这只是独立的轻量 Windows 脚本，须在 Windows 实机检查 Pillow、游戏前台及输入权限；**不等于旧控制器已经完整恢复，也没有常驻 F8 监听、已提交交易回执或业务安全验收**。

## 以后真正操作游戏

1. 先看 [极简工具手册](TOOLS.md)，使用新主线的 `game_io.py` 在当前 Windows 前台游戏上截图/悬停/查看详情，并在方案批准后执行合法输入；缺 Pillow 时由用户许可按 README 安装，不在实战中做新框架研发。
2. 如必须使用旧 Worker/broker，须在**独立的冻结目录或工作树**运行归档版本，明确旧版本的既有限制仍存在；它不会因新主线 README 变化就失去审批条件。该路径是兼容退路，不是本次已验证的带教版新输入器。
3. 任何输入操作都只允许一个实际控制者，遵守用户暂停/停止，窗口确认、输入已提交但后果未知时不盲重放。
4. 当前正在运行的 Windows 实例不会因为远端 GitHub 上创建新分支/合并而自动关闭。**不要在活跃进程使用原源码时强行 git pull、切换 main 或删除本地旧文件**；保护未提交修改。
5. 新工具若与旧 broker 的窗口互斥冲突，先停止旧控制权，再按原始身份记录确认真正退出；不得绕开互斥强行双控制。如新工具在 Windows 上无法成功截图/键鼠，应直说“当前只能做战略带教，无法自动点击”，不能伪造成功。

原版所有 483 个受版本控制的文件（含历史交接和生产源码）仍可从上述原始提交或归档分支读取。需要恢复时，可在**新目录**从归档分支检出，避免覆盖已有本地进度。旧版是否能启动仍取决于当时的 Windows 环境、输入桥注册和实际授权。
