### 正常路径：当前原生单动作

当原 Worker 自动请求已经 `kind=preparation_strategy / phase=startup_guide / page=preparation`，直接原 `decide` 即可，不需要先新建 ManualPhase。完整请求读原文件，不能用删了 rows 的展示投影：

```powershell

if ($q.kind -ne 'preparation_strategy' -or $q.preparation_checklist.phase -ne 'startup_guide' `
    -or $q.observation.page -ne 'preparation') { throw '先处理实际当前请求；不改阶段字段' }
$action = [ordered]@{
  type='click_point'; args=@(1687,65); expected_page='preparation'
  guard_texts=@('备战阶段','出战','商店')
  target_evidence=@{snapshot_id=$q.snapshot_id; bounds=@(1650,39,1727,94); control_id='prep_startup_guide_2'}
  reason='当前奖励已核领空，打开第二创业指南读取当前章节目标'

$reply = @{request_id=$q.request_id; snapshot_id=$q.snapshot_id; resume_epoch=$q.resume_epoch; actions=@($action)}
```

## 结果出口和失败分流

自动路径：`runner-state.json.startup_navigation_result` 及当前请求 `choices.startup_navigation`。手操路径：`$step.result.startup_navigation`。完整原记录在 `records/guide-navigation-<原战略request_id>.json`，runtime 的 `startup-navigation.json` 是当前指针。每张后继保存真实 PNG＋capture/frame/digest，展示 JPEG 不是该证据。

| 结果 | 下一步 |
|---|---|
| guard/来源零输入拒绝 | 保留旧拒绝；新 inspect、新 q/proof 后明确选当前行动，不改原证据 |
| queued/running 或交付 unknown | 同 job / 原 input ID 对账；无新点击，未知交付时不靠新图覆盖 |
| `expected_title_observed` | 只表明当前标题已读；ROOT 实读章节/目标/可领奖，并用原 startup ManualPhase 或当前 `preparation_review` 完成业务检查 |
| completed 但后继仍 unknown | 两次只读耗尽后停该自动动作；可继续原只读 inspect、按当前页复核。普通新 q 不能自动再点图标 |
| ROOT 当前仍明确需要打开第二图标 | 仅当原交付已确定 completed、全新 q/capture/frame，才接受新的显式主管 proof。新当前意图另有 input ID，链接旧 unknown；旧档案/旧点击/旧预算均不改。允许新 capture 的 PNG 字节恰好相同，不要求背景先动 |
| 页面/阶段/epoch/stop/deadline 改变 | 丢弃未发布旧动作；已发结果保留未知，不继承新页资格 |

在当前创业指南实际完成业务后，原 `manual-result` 的 review 仍须 `phase=startup_guide, stage=<实际>, reviewer=supervising_agent, completed=true, entry_index=2, rewards_claimed=true, goals=<实际目标列表>, findings=<实际说明>`，并列出该 checkpoint 后所有真实输入/control receipt ID。随后原 CAS resume 与当前来源复核；不能把上述导航 title 字段复制成阶段完成。买卖/D/F、奖励先行与每次 ROOT 出战验收不变。
