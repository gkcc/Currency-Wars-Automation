# 独立方法审查：OCR 是否适合作为游戏 Agent 的长期主架构

审查日期：2026-10-07。先完成本批 scope 代码、真实 PNG 测量和聚焦验收，再开展这项独立调研。没有调用额外模型、探测当前游戏、取得新游戏图或运行输入。结论是工程判断，不能冒充另一套方案已经在本游戏胜出。

## 决策

**不建议继续把“每一步全屏 OCR，再由主管逐笔处理正常动作”作为长期组织方式。建议保留当前唯一控制核心，转向按业务阶段分工的混合感知与本地机械闭环。** OCR 继续承担金币、费用、等级等需要精确来源的文字事实；已知控件用局部视觉定位；GPT/视觉理解处理完整场景、策略联动、未覆盖语义与必要选择。

这不是“马上换一个更大的视觉模型”。通用视觉模型可以直接处理截图，不必有单独 OCR 前处理，但理解文字、定位、回图和效果核验仍要发生。把已会执行的 D/F 或逐球领取重新放进每步模型推理，可能增加等待；是否更快、更准需对同一业务问题实测，现有官方资料不能替我们回答。

本批实测恰好阻止了一个错误乐观判断：[十图 warm 总实读](perception-scope/RESULTS.md) full 12.3426 秒、scoped 13.1078 秒，未证明总提速。跳过 StateReader 的事实不能掩盖主 OCR 未改变；主 OCR 的秒级成本也不能解释历史工具外 87.58 分钟。下一阶段不应继续围绕同一合同扩大测试数量，而应验证一类当前确实造成额外接管的能力缺口。

## 方法比较

| 方法 | 适合解决的问题 | 对本项目的限制 | 本次判断 |
| --- | --- | --- | --- |
| 当前 OCR、模板、确定规则 | 精确数值、已知控件、已有预算的机械循环 | 全屏文字流水线成本高；角色/布局/奖励语义覆盖不足；资料缺失会回传 | 保留可核事实和已会的动作；不把继续加字符串分支当作总方案 |
| 截图直接交通用视觉 Agent | 新页面、图标与文本关系、整体场景和复杂选择 | 本机延迟、目标定位错误、费用和阶段核验均未测；长任务可能产生额外恢复 | 作为有明确缺口的候选，不能默认逐帧替代 |
| UI Automation / 原生语义 | 应用实际提供的控件属性、状态和支持模式 | 是否存在真实业务控件 provider 未知；游戏窗口不等于网页 DOM | 将来只读证据若可用，优先针对可用字段取代像素读取 |
| 阶段驱动的混合方式 | 正常本地闭环，异常/选择/策略少量完整理解 | 必须规定何时升级、每种来源读什么；不能每帧全 OCR 后再全视觉而重复工作 | 当前最值得验证的方向，沿用现有 Perception/Worker/broker |

这里比较的是角色分工，并未选择或部署某个模型。现有经济循环最多八笔、一次预算授权，PR12 逐球本地推进，已经是可保留的基础；不能忽略已有能力后再新造同功能控制框架。

## 一手资料对结论的支持和限制

### 游戏 Agent 并不等于逐帧调用大模型

[Cradle 作者仓库](https://github.com/BAAI-Agents/Cradle) 把规划、记忆、技能和执行分开，迁移游戏需要专用技能与配置。作者还明确说明，部分实时游戏要暂停等待 GPT-4o。可迁移的是技能复用和反馈组织，不能据此宣称通用视觉已解决实时延迟。其仓库本次未提供能套用到本机的 P95。

[SIMA 2 论文](https://arxiv.org/html/2512.04797v1)（2025-12-04）用游戏数据训练 Gemini Flash-Lite，输入画面、输出键鼠动作块；另有较慢频率的 Gemini Pro 高层指挥实验。这支持快执行与慢推理分工，但低层能力依赖专门训练，不是换一段提示词即可得到。[2025-11-13 官方发布](https://deepmind.google/blog/sima-2-an-agent-that-plays-reasons-and-learns-with-you-in-virtual-3d-worlds/) 仍将其作为研究预览，并列出长任务、核验和精确操作等限制。

[UI-TARS-2 技术报告](https://arxiv.org/html/2509.02544v1) 给出了实际延迟交换：量化后平均交互轮端到端时间 4.0→2.5 秒，OSWorld 准确率 47.5→44.4。其游戏环境是提供同步状态的 HTML5/WebGL 沙箱。这些是该系统的平均数，不能当作本机 P95、本游戏成功率，或拿它与本次 OCR 时间直接排优劣。

[Voyager 作者论文](https://arxiv.org/html/2305.16291) 的可复用代码技能、执行反馈值得借鉴，但它依赖 Mineflayer 高层 API；作者明确不把结果与纯像素加低层控制直接比较。本游戏没有已经验证的同等接口，不能用论文中的便利前提替代现实。

### 桌面语义和直接视觉都有具体前提

[Microsoft UIA provider 概览](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview) 说明标准控件、自定义 provider 和客户端 proxy 如何暴露语义。能找到窗口不足以证明能读金币、卡槽或蓝球。未来若有授权的只读导出，应先看真实控件树和属性；本轮没有运行探针，当前可用性仍 unknown。UIA 属性与 PNG 也不是天然同一时刻的快照，新增来源需要单独绑定。

[OpenAI computer-use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use) 与 [Anthropic computer-use 指南](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) 都需要应用执行并回传观察，也支持短批次，不能说每个 click 都必然一次模型调用。模型生成的调用 completed 或工具 OK 不等于业务成功。Anthropic 明示延迟限制与批次首错后停止；这些原则可借鉴，但不授权把两颗球合并点击后补造单次效果。

[SikuliX Region](https://sikulix-2014.readthedocs.io/en/latest/region.html) 的局部搜索、出现/消失等待可复用到现有 OpenCV；其失败查找还会保留旧 lastMatch，因此不能照抄旧匹配点击。本项目仍应以当前帧重新定位。[Playwright 当前定位](https://playwright.dev/docs/locators) 和 [Microsoft 新缓存快照](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-cachingforclients) 提供对应的动态目标与快照原则，不证明游戏具有 DOM 或消除了截图后的异步变化。

## 最小架构方向

下一次实现仍只改现有观察/策略边界，不建立第二个控制器。

1. **观察契约负责“当前业务要知道什么”。** 本批 `full/rewards/economy` 是起点。每个字段保留 frame、来源和未读/未知状态，不能依靠某种模型自报 confidence 自动升级可信度。
2. **读取实现负责“如何取得事实”。** 精确数字保留局部 OCR；已有图标保留模板；可用的原生属性另列来源。完整视觉只用来评估目前规则缺失的语义，避免两套感知每帧都全量重复。
3. **Worker 负责正常状态推进。** 一次已核策略和预算可以驱动多次有后验的机械步骤。组合的是状态推进与重新定位，不是保存多串旧坐标。
4. **ROOT 负责真正需要的策略与验收。** 必要选择、未知效果、未覆盖页面和每次出战前验收保留。正常步骤不应因为缺一段固定接口而又退回 ROOT 临时写输入脚本。

当前全屏 OCR 还承担模态发现。短期不能直接裁掉中部文字：漏掉弹层后，底层备战锚点仍可能成立，unknown 回退不会触发。下一种观察实现必须同时解决这一全局状态判断，而不是只证明数字 crop 更快。换成视觉模型也不会天然消除 observe 与实际输入之间的时间窗。

## 已安排的下一项可判定任务

任务是**对当前确实不会识别的语义做纯离线观察对照，决定是否替换相应感知支路**。不再用新增合同测试数量作为结果，也不先承诺大模型胜出。

可先用现有 q/r 十图作为保留能力检查：q00 必须认出商店遮挡，q01 必须在本帧定位目标，q02 必须停止普通领取并指出提示，r00…r06 必须绑定玩家与金币。它们已经能由现有方案完成，新的视觉方案仅在这里追平并不足以支持重构。

真正的能力题优先选现有无遮挡 q01/q02 的阵容读取缺口：人口、占用、实名、星级分别输出；只核有人工来源的字段，不能把 5 个占用槽写成 5 个角色已经识别。若该题缺可核标签，最小补证是 ROOT 对已有两张图中**实际能确认的槽位、姓名、星级**给出标注或保留 unknown，无需新截图或导出完整私人素材。另一个候选是已有一例具体选择页，加当时未完成目标与可用资源上下文；必须对应一类本来会产生额外接管的缺口。

比较三个候选：现有读法、视觉观察提案、按需混合观察。它们读取相同当时可见图片和策略上下文；不得提前看后图、利用文件名答案或给其中一方补满 synthetic facts。输出只包含事实、目标与继续/回传原因，不发游戏输入。若还没有可用且获准的离线模型运行条件，推理延迟、费用和效果保持未测；本次仅完成资料审查和任务定义，没有虚构对照成绩。

评价只保留能改变决策的几项：

| 指标 | 具体判法 |
| --- | --- |
| 必要事实 | 分别统计正确、错误、未知、未读；只评当前业务所需字段 |
| 目标和停止条件 | 遮挡下领取、误买、错费用归属、未核阶段完成都单列；被共同守卫拦住的错误提案仍计恢复成本 |
| 不必要回传 | 区分必要策略、读图能力不足、调用方绕原生入口；不把必要出战验收当应消除的成本 |
| 业务节点成本 | 真读、规则、可选模型、发布/模拟执行、等待和恢复按实际区间计；重复/嵌套区间不能相加 |
| 已核终点 | 正确继续、正确选择/复核、证据不足停止；缺完整阶段证据就不计阶段完成 |

真实新帧读取与相同 PNG/提示缓存分别计时；各模型若有缓存也必须披露。现有数据量不足以可靠估计 P95或完整游戏成功率，不输出这些假精度数字。历史工具外 87.58 分钟不按次数平均分摊成模型思考时间。

**停止或继续标准：** 如果视觉方案既不修复一类实际额外回传，又比替代支路更贵更慢，停止替代；如果混合方案每张都要全 OCR 加全视觉，重新比较完整成本，不能只计其中一段。只有在真实失败样本上补足能力、保留必要事实与停止条件，并改善到达同一可核终点的总成本，才推进相应支路。出现无证据的完成或错误费用归属，则该候选本轮不通过。

完整单球后验仍需一笔真实单次领取的前后图和原回执；q01→q02 的两次点击组不能替代。UIA 可用性、额外模型本机成本、完整备战和整局速度都未在本轮验证。这个审查允许推翻当前 OCR 路线，也允许推翻纯视觉替代路线；唯一保留的评价目标是更快、可核地拿到实际奖励。
