## 4. B-001 接口与生命周期

控制器为每次观察生成 `frames/<请求ID摘要>-<随机帧ID>/original.png` 和 `preview.png`。先在同目录暂存、关闭写句柄、完整解码并校验 PNG，再发布唯一最终路径；后续请求不覆盖这些文件。

消费者使用实际请求返回的 result：

```python
frame = entry.observation_frame(run, result)
original = entry.observation_frame(run, result, original=True)
# 完成此请求所有读取，必要证据已保存到 records 后：
entry.release_observation(run, result)
```

读取验证请求 ID、帧 ID、路径归属、带时区捕获时间、SHA256、文件类型与体积上限、尺寸及完整解码。主管必须适配这个接口，不能继续读取 `game-preview.png`、`game-current.png` 或共享 `request-original.png`。旧协议会明确拒绝，不会退回旧画面。

worker 取得并验证下一帧后释放自己已消费的上一帧；战略请求的精确 PNG 和手操检查点先留在现有 records，供延迟验收。释放仅接受原请求台账中完全匹配的最终收据，不删除台账，不影响其他请求。帧抓取前有 384 MiB / 12,000 项容量检查，并预留本次原图与预览体积；容量不足只拒绝新观察，不驱逐未消费帧。

动作与观察结果分开：已进入可能发输入的调用记录 `input_attempted`、`attempted_actions`，失败位置另记 `failing_action_index`。`completed=[]` 不再能被下游当作零输入证据。输入后截图失败保留原完成收据，只做有界重新观察；若仍无可用帧，worker 暂停而不重发原动作。业务成功仍须钱、经验、库存、选择等当前差额证明。

Windows 共享冲突仅有界重试同一暂存文件的发布；没有重复抓取后重新发送输入。固定控制器 SHA256 为 `187F826FEB6E29BEAE8175CE9854845D19354F8344723C84663F6FE79EC0DCA5`，两处 pin 已同步。

后续优化先依据这些区间确认重复全屏 OCR、稳定知识重读和主管逐点击往返的实际成本，再用现有局部读取与状态驱动短循环削减重复。D 刷新已有语义路径；当前代码经验判断仍为 E（69），F（70）用于大世界交互。F 经验须本机核实键位后统一调整相关守卫，本批没有切换键位。

## 7. 本批采用的官方方法

- [Pillow Image 文档](https://pillow.readthedocs.io/en/stable/reference/Image.html)：`Image.open()` 延迟读取，`verify()` 不替代像素解码，因此同时做完整 `load()` 与结构校验。
- [Python os.replace](https://docs.python.org/3/library/os.html#os.replace) 和 [Windows 文件共享规则](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)：采用同目录暂存、关闭句柄、唯一文件发布及有限共享冲突重试，不宣称断电事务保证。
- [AWS 幂等重试实践](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)：沿用请求身份、原参数和最终回执对账，输入缺少服务端幂等保证时不自动重发。
- [Python 单调时钟](https://docs.python.org/3/library/time.html#time.monotonic) 和 [OpenTelemetry Trace 规范](https://opentelemetry.io/docs/specs/otel/trace/api/)：真实单调区间、请求父子关系及不同生产者边界；本项目仅借鉴计时组织方式，没有新增监控服务或输入框架。
