## 1. 结论与第一顺序

恢复骨架已经存在：同一请求回执对账、手操前后帧、阶段检查点、恢复 CAS、新 epoch、当前节点复核与变更隔离都有真实实现。应修正这些路径对失败和效果的处理，不再建设第二套任务框架。

先落实每请求不可变帧，再修恢复结果分级；随后处理 B-004 奖励容量例外和 B-005 统一经济依赖顺序与预算。计时可与第一批并行。原因是旧帧竞态会同时污染恢复、动作效果和性能归因，必须先建立可靠的证据来源。

恢复补丁不能用 `ok=False + completed=[]` 推断零输入，也不能用 PNG 哈希变化推断业务成功。旧回执缺少关键事实时保持未知；新帧只补观测，不重发旧动作。

## 2. B-003：已有能力与实际缺口

### 2.1 两种证据必须分开

请求层记录是否发布、完整已完成动作、仍不明的动作、原请求 ID 和原回执。业务层记录预期差额或后置条件，以及成功、零效果、部分、未知。使用简单字段即可，不给执行代理再添加长串状态名。

| 情形 | 能认定的事实 | 恢复处理 |
| --- | --- | --- |
| 发布前拒绝 | 发布点之前的结构化拒绝记录明确 `request_published=False`；不能单靠“找不到 ledger 文件”推断 | 旧动作未发布。重新观察并重算当前计划；只有当前身份、页面、预算仍满足时才能发布新的动作 |
| 已发布且证实零输入 | 原请求完整终态能证明业务输入函数尚未开始；或实际请求只包含 `observe` | 可保留不受影响的历史结果，但还要以新帧证明当前不变量。不能把零输入写成“阶段完成” |
| 所有动作已完成 | `completed` 与原动作序列完全一致；即使最后截图失败，已完成的动作也不能重发 | 单独补观察，以金币/经验/库存/选择状态等真实变化确认业务结果。截图成功不属于动作执行完整性的必要条件 |
| 输入已送出但业务零效果 | 新帧及足够完整的相关字段证明目标未变化；例如选项仅聚焦、选择计数仍为 0 | 记录零效果和真实剩余目标，由当前状态生成下一动作。不得直接重复旧坐标或累加已购数量 |
| 部分完成 | 只有可信的动作前缀完成，或目标差额只达成一部分 | 保留已完成部分与原回执，重新定位，只规划剩余业务目标；原批次整体不得重发 |
| 未知 | 无对应结果、结果身份不符、执行中断位置不明、低置信/冲突、节点改变或未涵盖的输入 | 不自动继承受影响阶段，也不自动重发；向主管回传原证据及缺哪项事实 |

重要源码反例：`control.execute_batch` 在整个 `click/key/drag/scroll` 函数返回后才追加 `completed`。`click`、`key` 发出按下/释放后最后的 `focus()` 仍可能抛异常；`drag` 也可在中途失败并于 finally 松键。因此 **空 `completed` 不是零输入证明**。若要在新回执中可靠证明零输入，应在既有控制路径记录动作进入边界；任何已进入可能产生副作用的动作，在没有完整结果前保持未知。不能补写旧回执。

另一个边界：`handoff_focus` 在切换前台时可能发 Alt 按下/释放。受控 resume 属于控制交接，不能谎称完全零系统输入；应记录确切恢复事件并重新确认页面。`wait` 批次如果带 `handoff=True` 也会经过该路径，不能仅按动作名一律视为纯观察。

### 2.2 当前必须修的三个细节

1. `finish_manual_phase` 当前的 `verified_change/verified_no_change` 仅比较前后 PNG 哈希。动态背景会改变哈希而购买未生效，界面短时不变也不证明动作无效果。该字段最多保留为“画面字节是否变化”，阶段完成仍由实际后置条件验证。
2. `review_preparation(manual_record=...)` 对 rewards/startup_guide 使用历史 after 帧。后续已记录的创业指南领奖等操作可能产生新箱/球；同节点不等于奖励仍领空。恢复后对奖励领空重扫当前备战帧；可能新增奖励的动作应使该前置条件失效。不能用旧 `all_claimed` 对新资源放行购物。
3. `consume_manual_results` 会将验收失败的 `(epoch, checkpoint_id)` 放入 `manual_results_rejected`。若只是弹窗缺节点或一次可恢复的观测失败，应有界等待当前合法节点帧后再验；身份不符、时间倒序、来源帧被改写、未覆盖变更仍明确拒绝。不能将这两类原因混用来无限重试。

### 2.3 必须重新核验的最少不变量

- 所属 run、游戏 PID/创建身份和窗口一致；原请求和恢复 CAS 链完整；当前 manual/stop/暂停优先级未被新的请求改变。
- 同一业务对局、实际当前节点一致；新 epoch 的当前请求、新帧和时间顺序有效。章节面板只有内容证据，不能代替当前节点证据。
- 奖励/箱/选择当前已处理完；库存空位和临时溢出独立于场上人口；动态金币、经验、角色、星级与任务进度来自当前回读。
- 阵容阶段核实名、位置、必需同场策略、装备及人口；战斗批准继续绑定当前单次请求，不能继承旧批准。

不要求每次恢复重读所有未变装备/羁绊说明。已经有版本依据的稳定知识继续缓存；当前拥有、穿戴、激活、进度仍是动态事实。

### 3.1 B-005：把经济动作放进有依赖的准备流程

最新强制顺序为：**全部奖励／选择 → 创业指南 → 无用牌出售 → 当前明确缺口购买 → 免费刷新并处理缺口 → 明确付费搜牌预算／停止条件 → 再决定人口经验 → 上场／装备／ROOT 出战验收。** 这应落在既有准备阶段和动作守卫中，不另建第二套流程或输入控制器。

当前最小改动是把 `economy` 阶段内部的依赖与预算写清：卖牌回读后确定可用总钱，先购买当前可信缺口，再用真实免费次数刷新并处理新缺口；接着给出付费搜牌目标、最多花费、有界停止条件和目标牌购买余量。没有付费搜牌需要时也要记录0预算与理由。强制搜牌的预算与停止条件未处理完成前，人口或经验动作不得先消耗买牌预算。满足目标、用尽预算／次数或满足停止条件后记录实际原因，才用剩余资源决定人口经验；发生未知或零效果先回传，不把它当作已完成搜牌。

每次出售、购买或刷新都回读金币、免费次数、实际库存和剩余缺口；不按计划次数累加成功。50利息储备、已选策略强制同场、攻略站位、升星／羁绊缺口和剩余回合共同影响预算；末期放开利息限制仍遵守上述顺序，不能把“花溢出”变成优先买经验的固定规则。

B-004 是该经济阶段的前置条件：奖励／选择必须当前领空，创业指南新奖励要回扫；满席时只允许为领取被容量阻塞的奖励而做必要腾位。该例外不授权普通出售、购物、刷新或升级提前执行，腾位后应立即返回领奖。人口数字与库存容量继续独立检验。

本机最新回报为同一未结束标准局的 `run_id=616b087bce2c4346a544d3802b2f19e0`、3-1、100血10连胜、7级38/52、52金币、飞霄8/9。它是后续验证的场景线索，不是云端已测状态，也不能将这些具体数值写成固定策略阈值。旧 worker 退出原因仍为 C-001；旧 broker PID 复用且本机未杀该进程，不补写原因。临时 ROOT 助手额外要求 `GetLastInputInfo` 派生闲置时长须 `>=500ms`，单列 B-008：本机回报按键集合为空而闲置读数仍0–80ms，现正改用既有 broker 可验证的光标／按键／前台 handoff；此项仅属于临时助手，绝不归为现有 broker 缺陷，修正尚待回传。

## 4. 最少验证与实机回传

优先扩展已有 `tools/test_local_runtime_compatibility.py::RuntimeCompatibilityTests`，沿用 `manual_bridge_fixture` 和现有回执替身；不新建通用测试服务。已有相关检查包括：`test_manual_bridge_partial_completion_survives_resume_without_blanket_completion_or_resend`、`test_manual_bridge_incomplete_or_omitted_receipt_stays_pending`、`test_takeover_receipt_reconciliation_waits_exact_id_and_never_republishes`、`test_manual_trace_does_not_survive_a_later_unrecorded_sale`、`test_manual_battle_acceptance_uses_current_population_instead_of_historical_full_team`。

其中名字带 partial_completion 的既有测试证明“只完成了部分准备阶段”，不是“一个输入批次部分完成后恢复已经正确”。不可把名字当覆盖证据。

建议为实际改变的合同补以下集中样本，不扩大全仓回归：

1. 发布前拒绝：没有输入发布；只重观察；重复同请求 ID 不出现第二次发布。
2. 已发送一次点击但末尾前台检查失败、`completed=[]`：必须未知，不判零输入，不复制阶段完成。
3. 动作完整而末尾截图失败：保留原完成收据；只补观察；实读差额证明成功后继续，发布次数不增加。
4. 阶段内一次明确恢复事件与最后回交：CAS/旧新 epoch/节点完整可对账；夹入新暂停、错误 pause_id、无关恢复或未知回执则拒绝。
5. 已成功领取奖励，随后纯观察失败：新帧核当前仍领空后可继续；若后续指南领奖新增箱/球，则回领奖阶段，不放行经济。
6. 章节弹窗缺当前节点：只暂缓自动继承；合法回到同节点新帧后验剩余阶段；换节点、旧帧或改 SHA 均拒绝。
7. 部分 XP 效果：例如请求 5 次但真实只增长 16 经验，剩余计划按实读差额生成；不把发出 5 次计为生效 5 次。
8. 任何恢复路径均不得改 `fully_read/confidence`，不得接受旧单次出战批准；满人口也不能替代实名/装备/溢出检查。
9. B-005 依赖：当前明确缺口或可用免费刷新未处理、强制付费搜牌预算／停止条件尚未处理完成时，经验动作应在发布前拒绝。逐次买牌／刷新后用新帧更新金币、免费次数和缺口；达到目标、预算／次数上限或约定停止条件后才评估经验，零效果或未知不能假记成搜牌完成。
10. B-004 容量例外：新帧证明满席阻塞领奖时，只允许必要腾位；普通经济仍被挡住。腾位后回读库存／钱并回领奖，指南领取产生新箱／球时重新扫场，不能继承旧领空标记放行搜牌。
