## 1. 历史耗时不能归因给未部署的循环

[历史记录](ROOT_PROFILE_FULL.json) 的 `code_sha` 是 `3878f9ce9cdf427efd2fe58539a93c3794fbf3f8`；实读该版本 runner，没有 `advance_economy` 或 `economy_plan`。旧 helper 标签中的 plan 也不能证明使用了后来新增的原生协议。因此，现有证据不支持“历史 ROOT 绕过已有原生经济循环”的归因。当前 PR14 已有该循环，但历史耗时不证明其实际接管率。[代码版本与事件绑定](economy-boundary/HISTORICAL_ENTRY_BINDING.json) 保留了两个真实提交的源码摘要、方法存在性和事件投影。

[耗时简报](OFFLINE_PERFORMANCE_BRIEF.md) 中，100.47 分钟只是部分窗口，宿主工具区间并集为 12.88 分钟，其外 87.58 分钟仍未分类。147 条 API 使用记录不能换算成 147 次必要策略；[逐节点标签](ROOT_STAGE_PROFILE.json) 只覆盖 77/99 条事件，没有完整节点起止。六次逐轮刷新与另一窗口五次本地循环的任务和终点不同，不能计算业务提速倍率。

几何/尺度、模板覆盖和字段依赖须分别诊断。[经济必要字段](../../tools/currency_wars_economy.py) 与 PR14 原生 D/F 路径不要求完整 team；购物则仍需当前目标实名、实价、槽位与策略计划。卡牌识别最终服务布阵、装备及出战，现有证据尚不能量化“只补实名能少几次回传”。

三个占用漏读与现有门槛可直接对应：前台第 4、可见后台第 1/2 的 badge 分数为 0.8275、0.8403、0.8557，均未达到 0.90；姓名候选也未达到实名阈值，不能作为第二条占用证据。原生卡框与人工近似框整体对应，只存在数像素偏差，不能凭此断定整体几何错位。星数读取要求完整 starbar 匹配及类间差，单颗星形不会被计为星数；现有审核没有 starbar 的逐模板尺寸、分数及位置，无法判定是尺度/裁切还是覆盖不足。

## 3. 本批选择：补原生入口事实

最大收益方向仍是把已授权计划内的机械动作留在本地，主管处理策略、异常和出战验收。当前缺口是无法区分“未进入循环、预算不适用、必要字段未知、原交易未决、完成守卫拒绝”，继续小修读取器无法回答这一业务问题。

本批只增加**可选 profile 点事件**，记录 `advance_economy` 的真实进入/退出、当前依赖及必要字段未知、预算作用域、pending 与完成守卫结果。复用既有 request/frame/epoch 关联及日志设施，不新增控制器、不改变策略、预算、业务顺序、输入或回执判断。具体实现字段、源码摘要、同终点验证结果与 Windows 命令由本批实现交付单独列明，本报告不预填通过或收益。

验收与后续优先顺序见 [ECONOMY_BOUNDARY_PROFILE.md](ECONOMY_BOUNDARY_PROFILE.md)。本批没有减少 ROOT 请求；实际收益是给下一次离线裁决提供可审查的停点，先验证刷新控件契约，再决定是否修改读取接口。

点事件用于解释控制流，不替代耗时区间。主管等待与其内部 OCR 等子区间不能相加；没有模型调用起止就保持未分类。离线可验证记录是否对应真实分支、开启/关闭是否保持相同终点；当前候选部署后的真实接管率和端到端收益仍缺实证。

## 4. ROOT 最小补证：只用既有资料

1. **刷新控件表达。** [留存 r00](refresh-sequence/r00.png) 的完整按钮显示币标与数字 2，没有显式免费次数 0。先核现有解析 ROI 是否覆盖完整按钮，以及免费/付费状态由文字、币标、价格或其他控件怎样表达；若已有免费态旧图，提供其现有索引对照即可。不要索要不存在的 `free_refreshes=0` 数字 ROI，也不能用之后扣了 2 币回填初始免费次数。暂缺互斥语义证据就保留未知。
2. **最小链路关联。** 从既有日志补一小段 event/request id → 原动作回执 → 前后图 SHA → 计划/预算记录 → 实际入口的对应关系。旧核心没有原生入口时如实记无该能力；若档案缺计划或调用关系就记缺失。无须导出整段聊天、全套知识或资源。
3. **同终点核验。** [六 D 旧子链](refresh-sequence/manifest.json) 保留原 wait(.4)，与候选 wait(.7) 不符的拒绝应继续成立；匹配的惰性协议须单列。初始预算、免费/付费语义及其他准备阶段未证明时，在真实阻塞点停止，不用合成 6/6 填满业务。卡牌素材仅在确定阻塞消费者后再给最小匹配项清单，不为 D/F 索取全阵容。

卡牌侧的备用诊断也只需留在本机运行：现有 q02 原导出 SHA `ffb4bb93d77eb9b96fa1860cd78595d2b7c1d4373061412982868c54cf00e366`，对 `front4/back1/back2` 加阳性对照 `front2`，返回 3 个 badge 模板的标识、摘要、尺寸、现有尺度、分数和匹配框；对 `front1/back1/back3` 的 3/2/1 星标签，只返回 5 个 starbar 的星数标签、摘要、尺寸、是否被尺寸检查跳过、分数/匹配框及不同星数候选差。这里的槽位名仅用于按几何对照，不能授权点击。无需导出图片、九个姓名模板或完整知识；本批经济复核不要求执行这组备用诊断。

## 5. 三项成熟实践及适配边界

- [MaaFramework 官方管线协议](https://github.com/MaaXYZ/MaaFramework/blob/main/docs/en_us/3.1-PipelineProtocol.md)：合法后继按序识别，动作后验证下一节点，提供区域、预期结果、超时及错误出口。项目适配推断：按阶段读取必要事实、在现有有界循环推进。其重复动作与错误重试语义不直接套到不可重复的购买、领奖；框架本身不引入。
- [Temporal 官方幂等说明](https://docs.temporal.io/activity-definition#idempotency)：外部动作可能完成而报告丢失；幂等键需由接受动作的服务实施。项目适配推断：游戏没有已证实的服务端幂等保证，request id/CAS 不能代替它，原 pending 与真实回执必须保留。
- [OpenTelemetry 官方追踪说明](https://opentelemetry.io/docs/concepts/signals/traces/)：区间记录有起止的操作，事件记录关键时点，关联表达异步因果。项目适配推断：借鉴事件/区间的职责，用现有记录解释入口和阻塞，不安装新服务、不把工具外时间命名为模型或 OCR。

## 6. 模型路线保持未接入

[Jev 既有审查](JEV_APPLICABILITY_REVIEW.md) 结论不变：文本/结构化状态决策不能补图像 unknown，无授权条件证明则不接在线服务。

今后若获得明确模型实验授权，可先固定一张已有图、一个阻塞字段，对比当前读取与一次视觉识别的准确性、来源、完整消费者成本及回退；同 SHA 的静态正文可复用，动态钱、商店、任务、装备和位置仍须当前验证。单帧实验不能证明跨帧稳定或整局收益。本批未做视觉实测，也不采用每帧全 OCR 再叠全视觉的方案。
